# 12 계획서 eCRF, 설문, 감사 체인

실행 호스트는 PC1 `MEDIIOT-SKLEE`다. 2026-10-29 격리 통합에서 확인한 내용만 적는다. 환자 원본과 DeeVo는 열지 않았다.

## 문제

계획서 버전, eCRF 스키마, 설문 응답, 감사 사건이 서로 다른 경로로 쌓이면 개정 추적과 변경 감사가 끊긴다.

## 구현 결정

Phase 012는 계획서 문서 레지스트리, eCRF 스키마 생성, OSDI 설문 응답·NA 채점·통계, append-only 감사 해시 체인을 추가한다. Phase 010 대시보드의 지연 응답 정리는 유지하고, 대시보드에 eCRF·설문 이동 버튼만 연결한다. 마이그레이션 헤드는 `medi012_questionnaire_engine`이다.

## 실험과 결과

컨테이너 Python 3.11.15와 일회용 PostgreSQL 15에서 SQLite 94 passed, 4 skipped, 정책 8 passed, PostgreSQL 양방향 각 4 passed였다. 내부 HTTP로 헬스, 대시보드, eCRF, 설문 페이지와 401·403을 확인했다. 호스트 브라우저 E2E는 수행하지 않았다.

## 아직 없는 것

운영 계획서 승인 상태 변경과 실제 환자 설문 입력은 이 통합에 포함하지 않는다.

## 다시 쓸 수 있는 설명

감사 사건은 이전 해시와 연결하고, 감사 기록 실패 시 본문 쓰기를 롤백한다.
